## 一、上线前必须做的配置

| 变量 | 线上取值 | 说明 |
|---|---|---|
| `ACCESS_PASSWORD` | **必填**，强口令 | 不配则 `/api`、`/media` 对公网完全开放 |
| `ALLOW_MOCK` | `0` | 未配 Key 的模型不再静默产出占位音频 / 模板歌词 |
| `FORCE_MOCK` | `0` | 同 V1.0 |
| `DAILY_COST_LIMIT` | 按预算，如 `30` | 生曲、出图、AI 素材在派发前按预估费用拦截 |
| `SELECTION_MODEL_KEYS` | `mureka,lyria,minimax` | 选型轮参赛名单；未配置凭证的模型在选型轮里不可勾选 |

部署步骤：
1. 在部署环境的 `.env` 里加上表中变量；
2. 前端产物已重新构建到 `backend/webapp/`，按原流程整包发布即可；
3. 首次启动会自动迁移数据库（只加列、打标记，不删数据），并按新口径重算模型战绩；
4. 用口令登录一次，确认看板正常。

> ⚠️ EdgeOne 自定义域名上的 `/media/*` 是静态镜像，**不经过后端，也就不受口令保护**（成片、缩略图可被直链访问）。
> 候选音频已改走 `/api/media/audio/<token>`（经边缘函数反代、受口令保护）。
> 如需成片也受保护，需在 EdgeOne 侧加鉴权或改为回源，属于部署侧工作。

## 二、改了什么

### 1. 安全与数据卫生
- **访问口令**（`app/auth.py`）：口令登录下发签名 cookie（14 天）；前端遇 401 显示登录页。`/api/health` 免登录供探活。
- **不再外泄服务器路径**：`/api/system/info`、`/api/health`、素材详情、授权清单 CSV、时间线接口均不返回绝对路径。
- **每日费用上限**（`services/budget.py`）：当日支出 = 音乐候选费用 + `ai_call` 记录费用。**生图此前完全不记费用**，现已按张计入（通义万相 ¥0.20/张，可用 `WANX_IMAGE_PRICE` 覆盖）。
- **mock / 种子数据隔离**：候选 `is_mock`、素材与素材卡 `is_seed`、素材 `source`（实拍 / AI）。AI 素材授权状态改为「AI 生成」，不再计入「已授权」。

### 2. 闸门与状态
- **后端闸门**（`app/gates.py`）：每个人工节点的「确认」由后端校验，不满足返回 409 并附逐条原因；去掉了配图闸门的 `force` 绕过。前端主按钮置灰并展示原因。
- **交付即锁定 + 新建修订版**：`delivered` 项目只读（配图 / 剪辑 / 歌词 / 生曲的写请求一律拦截，投放数据回填除外）；「新建修订版」复制简报与歌词，重新走检查与闸门。
- **检查结果以后端为准**：歌词版本新增 `checks_done`，前端只在检查完成后显示「通过」，修复「没歌词也显示三项检查全部通过」。
- **「确认简报」计入人工节点**；看板待办类型改为 简报 / 歌词 / 选曲 / 配图 / 精剪；时间戳统一带时区（修复「-24624 秒前」）。
- **轮询不再堆积**：前端同路径 GET 合并在途请求，轮询改为「上一轮返回后再发下一轮」。
- 加载中不再显示空状态（配图 / 剪辑 / 词曲的项目选择页）；配图页面包屑修复（原来恒为「—」）；弹窗支持 Esc / 点遮罩关闭。

### 3. 词曲
- **两种生曲模式**（`music_round` 表）：
  - 生产模式：一个模型出一首，显示模型名，不计入战绩；
  - 选型轮：参赛模型并行各出 N 版，**强制盲听**——接口、任务队列名称、报错、音频地址都不暴露模型；所有候选评分后才能选定，选定即揭晓。
- **战绩口径**：只统计已揭晓的选型轮；均分为 1–5 分（V1.0 显示的「12」是三项总和）；占位候选不计入。
- **歌词检查**：字数改为规则计算；改写建议必须是 6–12 字的整句，截断原句、只改尾字的建议直接丢弃（修复「雾还没江」「我想带你去桂林·」）；史实疑点在知识库上线前一律标「需人工核实」；「保留原文」必须填理由，且任何疑点都能保留（V1.0 没有建议的疑点连按钮都没有）。
- **生产环境不再产出模板歌词**：LLM 失败时报错并退回简报，而不是静默写出「我想带你去××」。
- 只有「待确认歌词」阶段能改词（之前生曲后仍能改词，导致歌声与字幕不一致）。
- 匹配分不再把模型名喂给 LLM。

## 三、存量数据（附录 B）的处理结果

迁移只打标记、不删数据：
- 3 个已交付项目全部锁定；它们各自仍挂着未处理的检查疑点（北京 3、永州 3、漓江 12）——这正是 V1.0 闸门可被绕过的证据。需要交付级质量时，用「新建修订版」重走流程。
- 漓江的 6 个占位候选标为 `is_mock`；V1.0 预置在它们上面的 4/4/4 评分不再进入统计。
- 模型战绩清零（还没有任何选型轮）。
- 18 条北京分镜素材改为 AI 来源；13 条 ffmpeg 合成的占位素材、2 张演示素材卡标为种子数据。

> 注意：本地库与线上沙箱库是两份数据。线上的「长白山·雪原」已在体验时推进到「待确认歌词」，本地库里仍在「简报中」。整包发布时以哪份为准，请按原发布流程确认。

## 四、测试

```bash
cd backend
.venv/Scripts/python.exe -m pytest tests -q
```

`tests/test_p0.py` 共 12 个用例，基于真实库的拷贝、在 Mock 模式下运行（不产生任何付费调用），覆盖：迁移结果、路径不外泄、口令、锁定与修订版、歌词闸门与保留理由、检查状态、建议过滤、生产模式与 mock 隔离、选型轮盲听与统计口径、费用上限、时间戳时区。

另做了浏览器端到端走查（Mock 模式）：登录 → 确认简报 → 写词 → 闸门拦截 → 保留原文 → 发起选型轮 → 盲听卡片 → 评分 → 选定揭晓 → 锁定项目只读 → 新建修订版。走查中发现并修复了 1 个缺陷：演示模式下选型轮未评分也能揭晓（已补回归用例）。
