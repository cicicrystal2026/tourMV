# 数字人接入方案（文旅 MV 逐镜头）

> 日期：2026-10-12 ｜ 基于对 `main@9bb7247` 的代码审计

---

## 0. 先看清现状：为什么现在画面里没有人

| 环节 | 现状 | 位置 |
|---|---|---|
| 出图 | **纯文生图**（`text_to_image(prompt)`），只传提示词，**没有参考图能力** | `adapters/image.py:152` |
| 提示词 | 景区/地标描述 + 「写实纪实摄影」后缀 + 负面词 → 产出**空镜** | `image.py:38` |
| 动起来 | 静态图 → ffmpeg **`zoompan` 缓慢推拉**（Ken Burns），不是真实运动 | `adapters/media.py:182` |
| 视频生成 | **完全没有**（无 text-to-video / image-to-video 适配器） | `adapters/` 目录 |

**结论**：想在每个镜头里加数字人，必须在这三处之一动刀。下面是三条路线。

---

## 1. 三条路线

### 路线 A · 出图阶段就把人画进去（参考图 / 角色一致性）

**做法**
1. 先定一张**角色定妆照**（虚拟角色，正面全身 + 指定服装），存为本项目的「角色卡」资产；
2. 给 `image.py` 加**参考图**能力：出图时把定妆照作为 `image` 参数一起传；
3. 逐句出图时 → 同一个人出现在不同景区。

**好消息：两家主力 provider 都原生支持参考图**

| Provider | 参考图参数 | 上限 | 备注 |
|---|---|---|---|
| 火山 Seedream 4.0 / 4.5 / 5.0 | `image`（URL 或 Base64） | **最多 14 张** | 同一个 endpoint 同时覆盖文生图与图生图/多图融合（传 `image` 即为图生图） |
| 通义万相 Wan 2.5/2.6/2.7 | `images` / `image_url` 数组 | 最多 9 张 | Wan 2.5 i2i 主打「主体一致性保持与多图融合」 |

- 改动量：**小**（`image.py` 加参数 + 分镜加字段）
- 一致性：中（参考图能"很像"，但非 100%；用结构化角色描述可提升）
- 运动：无（仍是静图 + Ken Burns 推拉）
- 成本：**几乎不增**（参考图不额外计费，仍约 ¥0.2/张）

### 路线 B · 空镜出图 + 数字人后期抠像叠加

**做法**：出图保持空镜（**已审的图全都不用重做**）→ 单独生成数字人表演片段（带 alpha）→ 在 `image_to_clip` 之后加一步 ffmpeg `overlay` 合成。

- 改动量：中（新增合成步骤 + 逐镜头调位）
- 一致性：**最高**（同一份人物素材复用，天然一致）
- 运动：人物的运动来自数字人素材本身
- 成本：数字人平台费 / 素材制作费 + **逐镜头调位的人工工时**（随镜头数线性增长）
- 主要风险：**光影与机位不匹配 → 像贴纸**。这是最容易翻车的一环。

### 路线 C · 引入图生视频（image-to-video）

**做法**：首帧图 → 图生视频模型（Seedance / 可灵 / 即梦视频等）→ 画面**真正动起来**，人也自然融入。

- 改动量：**大**（新增一类适配器 + 队列 + 成本控制 + 质检）
- 一致性：中（仍需参考图兜底）
- 运动：**真实**
- 成本：**数量级上升** —— 约 **¥1–5 / 秒** × 137 秒 ≈ **¥150–700 / 条**
  （当前整条 MV 是 ¥3.97，即 **40–180 倍**）

## 2. ⚠️ 必须先说的四条红线与坑

### 2.1 【决定方案可行性】参考图不能是真实人物

火山方舟对 Seedream 图生图有明确约束：

> **图生图若产出仍含真实人物身份，会被内容审核拒绝（防深伪），请使用合成脸或非真人素材。**

**含义**：
- ❌ 不能拿明星 / 网红 / 素人的真人照片做角色参考图（会被拒）
- ✅ 只能用**纯虚拟角色**：先文生图造一个虚拟形象，再拿它当参考图

这条**恰好与项目既有红线一致**（不做 AI 仿冒他人形象 / 音色）。

### 2.2 数字人模仿真人有法律风险

与「不做 AI 仿唱他人声线」同理 —— 未经许可模仿特定自然人形象，
可能同时侵犯**肖像权**与（若含声音）**声音权**。
杭州滨江法院 2026-07 判例：AI 处理后的声音/形象只要能让普通听众识别出特定自然人，即受保护。

### 2.3 纯 AI 虚拟形象可能拿不到著作权 → 冲击交付要件

政府采购普遍要求**「著作权永久归采购方」**。而**纯 AI 生成物因人类独创性贡献不足，
著作权归属存在争议**（可能不被认定为作品）。

**含义**：如果整条片子的"人"完全是 AI 造的，甲方可能拿不到可确权的成果 → **交付本身受影响**。

**缓解**：角色设计必须有**人的实际参与**并留痕（原创角色设定文本、手绘草图、
真人出演的形象授权书、造型设计稿）—— 这也是项目「人机共创可确权」思路的延续。

### 2.4 第三方数字人平台（腾讯智影 / HeyGen / D-ID 等）要先查授权范围

- 这类平台输出多为**半身、固定机位、纯色或简单背景**的口播视频，
  直接贴进文旅实景**融合度差**；
- 更关键的是**商用授权范围**：与剪映「商用音乐」同类陷阱 ——
  很多平台只授权"平台内发布"，文旅要投**视频号 / 小红书 / 海外**，很可能超范围。

## 3. 我的专业建议

### 3.1 不要「每个镜头都有人」

这几乎肯定不是好选择。真实 MV 的语法是**人物与空镜交替**：

- **空镜**承载**地域气质**（这是文旅的核心卖点，也是甲方要的真实景区）
- **人物**承载**情感主线**

每个镜头都塞人会带来三个问题：
1. **视觉疲劳** —— 观众失去"这个人什么时候出现"的期待；
2. **一致性破绽被放大 17 倍** —— 参考图做不到 100% 一致，露脸越多越容易看出不是同一个人；
3. **成本翻倍**（走路线 C 时尤其致命）。

**建议**：人物出现在 **5–7 个镜头（约 1/3）**，且集中在**副歌与情绪高点**，
用「人物锚点」而非「人物覆盖」。

### 3.2 推荐的分阶段路径

| 阶段 | 做什么 | 成本 | 验证什么 |
|---|---|---|---|
| **1（先做）** | 路线 A 最小版：加「角色卡」+ 参考图能力，**先只做 3 个镜头**试效果 | ≈ ¥0 增量 | 一致性到底能不能接受 |
| **2** | 若可接受 → 加「人物出现策略」（分镜规划时决定谁有人） | ≈ ¥0 增量 | 人物与空镜的节奏是否好看 |
| **3（按需）** | 只有当"必须动起来"时才评估路线 C | ¥150–700/条 | 值不值这个钱 |

**理由**：路线 A 的增量成本接近零，却是**唯一能立刻验证"一致性"这个最大不确定性**的方式。
如果连参考图都对不齐，路线 B/C 也救不了。

## 4. 路线 A 的落地方案（具体到字段与文件）

### 4.1 数据模型

**新增：项目级角色卡**（复用 `asset` 表现成也可，但建议独立以便管理）

```
project.persona_id  → 指向一张"定妆照" asset（type=persona）
```

**`storyboard_shot` 加 3 个字段**（`models.py:251`，走 `db.py` 的 `_ADDED_COLUMNS` 增量迁移）：

| 字段 | 用途 |
|---|---|
| `person_present` | 本镜头是否出现人物（bool）—— **由「出现策略」决定，不是全 true** |
| `person_action` | 人物动作/位置/景别（如「中景，背身走向桥头」） |
| `person_ref_asset_id` | 该镜头使用的角色参考图 id（留空则用项目默认角色卡） |

### 4.2 代码改动点

| 文件 | 改动 |
|---|---|
| `adapters/image.py` | `text_to_image()` 增加 `ref_images: list[str] \| None`；`_seedream()` 传 `image` 字段（≤14 张）；`_wanx()` 走 i2i endpoint |
| `services/storyboard.py` | `plan()` 里为每个镜头决定 `person_present` 与 `person_action`；`_render_one()` 出图时带上参考图 |
| `services/prompts.py` | 分镜规划提示词加「人物出现策略」约束（目标 ≈1/3 镜头）；提示词里拼入结构化角色描述 |
| `services/render.py` | 无需改动（仍是静图 + 推拉） |
| 前端 `pages/Storyboard.tsx` | 审核页展示角色卡、逐镜头可切换「有人/无人」、可换参考图重出 |

### 4.3 角色一致性提示词（实测有效的写法）

用**结构化角色描述**，每行一个「名词 + 限定词」，只写**不可变特征**，
不要混入动作与场景（混入会失效）：

```
齐耳短发带右偏分
心形脸下颌线清晰
内双浅棕虹膜
左耳三枚银色圆环耳钉
暖调中等偏深肤色
靛蓝棉麻立领上衣
```

这 6 行由**同一张定妆照**逐项确认而来；**混用不同图的特征会导致模型混淆**。
