# 镜头节奏改造：「一句歌词 = 两个连贯画面」

> 起因：用户试听反馈「演唱一句歌词时一个画面太慢，PPT 感」，要求每句歌词给两个连贯镜头、有动作感。
> 结论时间：2026-10-12

---

## 一、先量化诊断：PPT 感的真正来源不是「切得慢」，是「压根没动」

现状一个镜头的平均时长是 **5.7 秒**（E2E 项目实测 17 句 / 137.7 秒，句子 2.6–8.7 秒），
这个长度本身在 MV 里**不算慢**——常规 MV 单镜 2–4 秒，5 秒也不算事故。

真正的问题是**画面动不起来**。`adapters/media.py::image_to_clip` 里：

```python
amount = 0.10                 # 整条素材只推近 10%
rate = amount / frames        # frames = 20 秒 × 25fps = 500 帧
```

推近的步长是按**整条 20 秒素材**摊算的，而每个镜头实际只用到其中 4–6 秒。
于是真正落在画面里的运动量是：

| 段落时长 | 实际推近幅度 |
|---|---|
| 3.0s | **1.50%** |
| 5.0s | **2.50%** |
| 5.7s（典型） | **2.84%** |
| 8.7s | **4.34%** |

**2.8% 的画面放大，肉眼完全看不出来** → 观众看到的是一张静止的图挂着 5.7 秒。
这就是「PPT 感」的全部来源，和切镜长度关系不大。

顺带发现第二个失效：`edit._split_static()` 的设计意图是「同一张图按不同时间窗取
远景/近景，做出景别递进」，但它依赖素材本身有明显推近——
而推近只有 10%/20s，两个窗口之间差不到 3%，**这套机制实际上从来没生效过**
（阈值 `MAX_STATIC_S = 8.0` 也偏高，17 句里只有 1 句超过）。

## 二、三条路线与成本

成本基准：E2E 项目实测总成本 **¥3.97**，其中**出图 ¥3.57 占 90%**
（17 张 × Seedream 5.0 flash ¥0.21/张），音乐 ¥0.324，其余 ¥0.078。

| 方案 | 张数 | 图片成本 | 项目合计 | 涨幅 | 说明 |
|---|---|---|---|---|---|
| 现状：每句 1 张 | 17 | ¥3.57 | **¥3.97** | — | 基准 |
| **A：运镜强化（不加图）** | 17 | ¥3.57 | **¥3.97** | **+0%** | 把推近幅度提到 42%/20s，并按景别差异取不同时间窗 |
| **B：每句 2 张** | 34 | ¥7.14 | **¥7.54** | **+90%** | 真正的两个画面，景别递进（远景全景 → 中近景细节） |
| B′：仅 ≥5s 的句子拆 2 张 | 29 | ¥6.09 | **¥6.49** | +63% | 短句（2.6–3.5s）不拆，避免 1.3 秒一闪 |
| 折中：只副歌段拆双镜 | 25 | ¥5.25 | **¥5.65** | +42% | 主歌单镜、副歌双镜，节奏对比反而更好 |

### 耗时影响

| 张数 | 并发 3（现值） | 并发 6 |
|---|---|---|
| 17 | 1.5 分钟 | 0.8 分钟 |
| 34 | 3.0 分钟 | 1.5 分钟 |

出图阶段会从实测的 320 秒增加到约 600 秒，把 `IMAGE_CONCURRENCY` 提到 5–6 可压回 ~350 秒
（注意厂商限流，`storyboard.py` 里已 clamp 到 6）。

### 真正的成本不是钱

**是人工审图量翻倍**：17 张 → 34 张，逐句通过/重出的人力翻倍。
相对于政采 18 万的预算，多花 ¥3.6 可以忽略；**多审 17 张图才是要花人时间的地方**。

## 三、推荐路径

**A 现在做（今天、零成本、立刻见效），B 作为可配置项。**

> ✅ **方案 A 已于 2026-10-12 落地**（最终取值见下表，与本节原估的 0.42/3.5 略有调整：
> 幅度定 **0.50**、阈值定 **4.0**，并新增 `PRE_SCALE=1.5` 保证不发糊）。
> 实测：镜头数 24 → 42，成片 137.4s ≈ 音频 137.7s，42 个测试全过，
> 片段生成代价 2.2s → 2.9s/条。老项目用 `_probe/reclip.py` 重出片段即可生效。

| 参数 | 值 | 位置 |
|---|---|---|
| `PUSH_AMOUNT` | 0.50（可用环境变量覆盖） | `adapters/media.py` |
| `PRE_SCALE` | 1.5 —— **必须 ≥ 1 + PUSH_AMOUNT** | `adapters/media.py` |
| `MAX_STATIC_S` | 4.0（原 8.0） | `services/edit.py` |

1. **先做 A**：把推近幅度按「实际使用时长」而不是「整条素材」设计，
   同时修好 `_split_static` 的景别递进逻辑。**一分钱不花**，
   单镜运动量从 2.8% 提到 10%+，同时把镜头上限从 8 秒降到 3.5 秒左右。
2. **再开 B**：让「每句几个画面」成为项目级配置（默认 2）。
   需要成对生成提示词，所以必须配人工审核。

如果预算敏感，**B′ 是性价比最高的一档**——短句本来就只有 2.6–2.9 秒，
再拆成两个 1.3 秒的镜头反而会碎。

## 五、两个必须提前规避的坑

**① 成对画面的「穿帮」风险。** 两张图分别生成时，光线/天气/季节可能不一致
（一次出上午逆光、一次出傍晚暖调），切过去就穿帮。
缓解：提示词里把**光线、天气、季节、色调**作为**逐字相同的固定串**下发，
只让景别与主体变化；审核页要有「成对看」的视图，不然人眼比对不出来。

**② 同一地点两个景别 ≠ 两个地点。** 「连贯」在剪辑语言里是**空间连贯**
（同一场景的不同景别），不是「两个不同景点」。如果两张图是两个地方，
切过去是跳切而不是连贯，观感反而更差、更像 PPT。

## 六、验收方式

改完必须核这三条（否则等于没改）：

```bash
# 1) 单镜运动量：抽同一镜头的首末帧，算画面主体尺寸变化是否 ≥8%
ffmpeg -ss 0.2 -i clip.mp4 -frames:v 1 f1.jpg
ffmpeg -ss 3.0 -i clip.mp4 -frames:v 1 f2.jpg   # 目视或做像素差

# 2) 成片时长必须仍等于音频时长（这是老坑，改渲染必查）
ffprobe -v error -show_entries format=duration -of csv=p=0 成片.mp4

# 3) 镜头数：timeline_clip 条数应约等于「歌词行数 × 每句镜头数」
```

## 七、实测中发现的另外两个 PPT 成因（比分镜运动更严重，**均未修**）

实施 A 的过程中拿 E2E 项目实测，发现两处比「运动幅度小」影响更大的问题。

### 1. 分镜提示词重复 → 17 句只生成 12 张不同的图

第 7–10 句的 `place` 与 `prompt` **逐字完全相同**：

```
#7  婺源啊，是等你的地方    → 婺源县江湾镇汪口码头
#8  不是归途，却像故乡      → 婺源县江湾镇汪口码头   ← 提示词与 #7 一字不差
#9  千叠山色低垂成守望      → 婺源县江湾镇汪口码头   ← 同上
#10 一盏茶凉，人未返航      → 婺源县江湾镇汪口码头   ← 同上
```

去重后**唯一提示词数 = 1/4**，于是生成 4 张一模一样的图 →
**连续约 20 秒是同一张静止画面**。（#13/#14 同样重复，合计 17 句 → 12 张唯一图。）

**根因**：`mark_dups()` 只按**歌词文本**去重（这是为副歌复唱设计的），
**不检测提示词/景观重复**，所以这类重复既不会被标记也不会被审核页提示。

**修法**：`plan()` 之后加一道提示词去重 —— 发现连续相同的 `place`/`prompt` 时，
**保留同一地点**（空间连贯），但强制拉开**时段 / 视角 / 景别 / 主体**，
让它们变成「同一场景的不同镜头」而不是同一张图。这也正好是用户要的
「一句歌词两个连贯画面」的正确形态。

### 2. 尾奏 49 秒只有一张图

`edit.auto_cut` 的「收口」逻辑把最后一个镜头延伸到音频末尾。
E2E 项目末句歌词在 **88.3 秒**结束、音频 **137.7 秒** →
最后一段长达 **49.4 秒**，被 `_split_static` 拆成 **11 段同一张图**
（按 11 级景别逐段推近），观感是「同一张照片跳切 11 次」。

**修法**：器乐段落（前奏 / 间奏 / 尾奏）改用**多张已审核配图轮播**作为 b-roll，
而不是沿用最后一句的那张图。前奏目前也有同样的隐患（只是较短）。
