## 二、唯一待办：申请免费 HTTPS 证书

### 现象

443 端口是通的、TLS 1.3 握手正常、HTTPS 路由全部返回 200（关闭校验后实测），
但服务器出示的证书是腾讯云 CDN 的**共享默认证书**：

```
subject : CN=*.cdn.myqcloud.com
issuer  : WoTrus RSA DV SSL CA 2
altnames: 56 个条目，均为 *.cdn.myqcloud.com / *.qpic.cn / *.gtimg.com 等
          —— 不包含 tourmv.migucomi.com
```

浏览器访问 `https://tourmv.migucomi.com/` 会显示「证书无效 / NET::ERR_CERT_COMMON_NAME_INVALID」。
目前 **HTTP 可以正常访问**（没有强制跳转），所以站是能用的，但不适合对外交付。

### 操作步骤

1. 登录 EdgeOne Makers 控制台，进入项目 `wenlv-mv`
   直达：https://console.cloud.tencent.com/edgeone/pages/project/makers-0qb3g9ejo0aq
2. 左侧导航栏点击 **域名管理**
3. 在域名列表找到 `tourmv.migucomi.com`，在 **HTTPS 列**点击「配置」
4. 找到「**边缘 HTTPS 证书**」卡片，点击「配置」
5. 配置方式选择「**申请免费证书**」，验证方式选择「**自动验证**」，点击保存
6. 等待 5–30 分钟，证书由 CA 签发后自动部署；回到域名管理页可看到状态变为「已部署」

> **为什么推荐「自动验证」**：域名的 CNAME 已经正确指向 EdgeOne 且没有分线路解析，
> 完全满足自动验证条件，无需手动加 DNS 记录。
>
> **免费证书说明**：由 TrustAsia / Let's Encrypt 签发，有效期 90 天，
> 到期前 15 天平台自动续期，无需手动维护，但**不支持下载、无 SLA 保障**。
> 如果要对外正式商用，建议在腾讯云 SSL 证书控制台购买后选「申请 SSL 托管证书」方式部署。

## 三、本次额外修复的问题：API 接口约 1/3 概率 504

验收过程中压测发现了一个比证书更影响体验的问题，已修复。

### 现象

经 EdgeOne 边缘访问 `/api/*` 时，约 **1/3 的请求返回 504**（EdgeOne 平台的错误页，2597 字节 HTML），
表现为前端页面「转圈后报错、刷新一下又好了」。

### 定位过程

| 路径 | 成功率 | P50 | 说明 |
|------|--------|-----|------|
| 源站直连 `tourmv-pipeline.app.workbuddy.host` | **15/15 → 59/60 (98%)** | 892ms | 后端本身是好的 |
| 经 EdgeOne 边缘 | **10/15 → 54/60 (90%)** | 2086ms | 卡在边缘这一跳 |

关键证据：`/api/health` 这个接口**只返回一个常量字典、完全不碰数据库**，却要 0.8–8 秒。
这说明瓶颈不是业务代码，而是**沙箱后端进程本身**（冷启动 / CPU 抢占）。
源站单请求 0.6–2.7 秒，叠加跨境回源往返后，会顶到平台网关的等待阈值，
平台直接掐断并返回 504（不是我们代码返回的 502）。

### 修复措施

**1. 边缘函数对幂等请求自动重试**（`wenlv-mv-edgeone/edge-functions/api/[[default]].js`）

- 只对 `GET / HEAD / OPTIONS` 重试，最多 2 次，带 200ms 抖动退避
- 写请求（`POST / PUT / PATCH / DELETE`）**绝不重试** —— 否则会重复创建项目、重复入队生成、重复扣费
- 用 `eo.timeoutSetting` 把单次尝试的读超时收窄到 12 秒，让失败尽早暴露、把时间预算留给重试

效果：**504 从 4/15 降到 0**，成功率 17/18。

**2. 前端 GET 请求自动重试**（`frontend/src/lib/api.ts`）

- `req()` 对 GET/HEAD 失败重试，最多 3 次（300ms / 600ms 退避 + 抖动）
- 只重试网络错误和 502/503/504；4xx 业务错误直接抛出，不浪费重试
- 写请求一次都不重试，语义与边缘函数一致
- 单请求 20 秒超时（AbortController）

### 仍存在的限制

边缘相比直连多约 **1.2 秒**开销（跨境回源 + 重试兜底），P95 偶发到 12 秒。
对 MVP 演示够用，但如果要支撑真实用户量，架构上需要二选一：

- **把后端搬到国内云服务器**（腾讯云轻量/CVM），走 EdgeOne 普通回源而不是边缘函数反代；
  延迟可从 2 秒降到 200ms 级，同时解决大陆加速问题（需 ICP 备案）
- **在边缘加接口缓存**：对 `/api/state-machine`、`/api/system/info`、`/api/music/models`
  这类低频变更接口用 Cache API 缓存 60–300 秒，可显著减少回源次数

## 四、架构备忘（为什么是现在这个样子）

```
浏览器
  │
  ├─ /  /dashboard  /assets/...  /media/renders/*.mp4
  │      └─→ EdgeOne CDN 直出（静态资源优先于边缘函数，不产生函数调用）
  │
  └─ /api/*
         └─→ EdgeOne 边缘函数 edge-functions/api/[[default]].js
                └─→ 反代到 WorkBuddy 沙箱后端 tourmv-pipeline.app.workbuddy.host
                       └─→ FastAPI + SQLite + 队列 worker + ffmpeg
```

后端没有搬到边缘，是因为它依赖 **SQLite 写库、本地媒体文件、ffmpeg 子进程、常驻队列 worker**，
Serverless 环境没有持久磁盘、没有 ffmpeg、没有常驻进程，跑不了。

### 关于「国内是否都能打开」

项目加速区域选的是 **「全球可用区（不含中国大陆）」**，这样**无需 ICP 备案**即可绑定自定义域名。
代价是：大陆用户访问会被调度到境外节点（中国香港 / 新加坡等），能打开但延迟偏高。
如果需要**大陆节点加速**（延迟降到几十毫秒），必须完成 ICP 备案后把加速区域改为含中国大陆。

## 五、成片这类大文件：发布包不带，线上回源

加入「文生图真实素材 + 多版本成片」之后，本地 `data/` 涨到 **330MB**
（成片 223MB / 音乐 48MB / 素材 25MB / 图片缓存 25MB），而沙箱发布对体量很敏感：

| 目录体量 | 沙箱发布 |
|---|---|
| 65 MB | ✅ |
| 82 MB | ✅ |
| **330 MB** | ❌ 报 `sandbox /workspace is empty after upload/extract` |

⚠️ 这条报错的文案有误导性 —— 它**不止**是「路径要用反斜杠」那个坑，
**体量太大时也是同一条报错**。看到它先确认路径写法，再 `du -sh` 看体量。

对应的做法是**让发布包不带成片**：

- 发布前把 `data/renders`、`data/images` 临时移到项目**外**（如 `_publish_holdout/`），
  发布完成后移回 —— 发布只是快照，移出去的目录不会进包。
- 线上后端在 `MEDIA_FALLBACK_BASE` 指向的地址（本项目的自定义域名，EdgeOne CDN）
  **回源**取成片。`/media/renders` 因此是一个自写路由（不是 `StaticFiles`）：
  本地有文件就直出、没有才回源，并透传 `Range` 支持拖拽播放。
- 顺带：EdgeOne 那边能吃下 295MB（30 秒部署完），所以成片放 CDN 完全没问题，
  真正吃不下大包的是 WorkBuddy 沙箱发布。

### 两个实现要点

1. 自写媒体路由**必须显式声明 `HEAD`**（`StaticFiles` 自带，自己写容易漏）——
   验收大文件完整性靠的就是 `HEAD` + `Content-Length`。
2. 回源拼 URL **不要对已解码的路径参数再 `quote()`**：框架已经把 `{filename}`
   解码成中文名，再编码会变成双层编码（`%E6%B0%B8` → `%25E6%25B0%25B8`），
   CDN 直接返回 **403**。要用 `request.scope["raw_path"]`。
